# Results Directory & Reproduction Protocol

This directory is designated for experimental outputs generated by the benchmarking scripts.

## File Organization & Naming Conventions

When benchmarks are executed, results are saved with the following standardized naming pattern:

```text
results/
├── system_info.json                # Hardware, driver, and PyTorch environment details
├── {system}_{mode}_c{c}_r{r}.csv   # Raw per-request latency trace
├── {system}_{mode}_c{c}_r{r}.json  # Summary metrics for that trial run
├── {system}_{mode}_gpu.csv         # Background NVIDIA-SMI telemetry trace
├── comparison.csv                  # Aggregated dataframe from all JSON trials
├── comparison_summary.csv          # Grouped mean/std metrics by system, mode, concurrency
├── comparison_throughput_mean.png  # Throughput comparison chart
└── comparison_p95_latency_mean.png # p95 Latency comparison chart
```

- `{system}`: Hardware identifier (e.g., `4060`, `5060`, `desktop`).
- `{mode}`: Active batching policy (`none`, `fixed`, `adaptive`).
- `{c}`: Concurrency level (`1`, `4`, `16`, `32`).
- `{r}`: Trial repetition index (`1`, `2`, `3`).

## Data Policy & Scientific Integrity

- **No Fabricated Data**: This repository contains only verified, reproducible empirical results. Missing configurations (e.g., before fixed or adaptive benchmarks have been run) must remain absent rather than artificially generated.
- **Git Tracking Policy**: High-volume raw CSV traces and ephemeral JSON run artifacts are excluded by `.gitignore` to prevent repository bloat. Only aggregated summaries, system metadata, and documentation are tracked.
- **Multi-Laptop Result Merging**: When comparing two laptops, rename `system_info.json` to `{system}_system_info.json` (e.g., `4060_system_info.json` and `5060_system_info.json`) prior to merging folders so hardware metadata is preserved.
